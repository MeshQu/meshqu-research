# Prompt for the iko-tools session

Copy-paste the section below as the opening prompt of a new Claude Code session inside the iko-tools repo. Attach the files listed under "Files to attach" before sending. (Or paste their contents inline if your iko-tools session takes attachments differently.)

## The prompt

You are continuing the publication pipeline for the MeshQu Research Programme. Experiment 1 (E1 / MRP-2026-02, published 2026-05-18) used the doc engine and chart curation in this repo. Experiment 2 (E2) is now at the figure-production stage, planned for publication as MRP-2026-03.

The writeup itself lives in a sibling repo (`meshqu-research`) and is not yours to edit. Your job in this session is narrow: **produce the six inline figures for the E2 writeup, in the same journal style as MRP-2026-02, using the figures spec attached.**

### Inputs

1. **`figures-spec.md`** — the load-bearing input. Per-figure caption (verbatim from the writeup, do not edit), primary data tables (extracted from the corpus so you don't have to re-derive), chart-type recommendation, highlight notes, and source-of-truth pointers. Treat the captions as locked copy; treat the data tables as canonical.
2. **`writeup-DRAFT.md`** — read for context to see where the six figure callouts live in the writeup body, and to confirm cross-reference numbering. Do not edit this file.
3. **`01-per-level-summary.md` through `07-token-cost.md`** — the seven Phase 3.1 cross-level-analysis notebooks. These are the primary data source if any number in `figures-spec.md` needs verification.
4. **MRP-2026-02 source files** (already in this repo) — your reference for E1's chart conventions: colour palette, caption placement, figure-number formatting, font stack, aspect ratios, annotation style. The figures-spec has a checklist of E1 conventions under "Style anchors to E1" — resolve those checkboxes against MRP-2026-02 once, then apply consistently across all six E2 figures.

### Deliverables

- **Six rendered figures** (Figures 1, 2, 3, 4, 5, 6) in whatever format MRP-2026-02 used (SVG / PNG / inline). Numbering matches the spec exactly.
- **Figure 3 is the load-bearing graphic** of the paper. Spend the most styling time on it. The visual must instantly communicate flatline → flatline → flatline → spike → partial regression across L0..L4.
- **MRP-2026-03 publication artefact** assembled per the iko-tools doc-engine convention. The writeup body comes from `writeup-DRAFT.md`; figures slot in at the existing callout points. The DRAFT prefix in the H1 should be stripped only when publishing — keep it while assembling.

### Visual register (load-bearing, restated from the spec)

Restrained, systems-oriented, research-grade. Visual reference points: Anthropic system cards / IBM Research / Stripe engineering reports / government digital-service reports / academic systems papers. **Avoid** glossy AI imagery, gradients, decorative futurism, neon palettes, startup-infographic styling. If MRP-2026-02's palette established a verdict-state colour discipline, follow it; otherwise pick neutral mid-tones that don't read as policy-violation marketing.

### What's out of scope

- Editing `writeup-DRAFT.md` (the writeup is in another repo; if you need a change there, flag back to Sam — do not patch around it)
- Composing new captions (the captions in the spec are verbatim from the writeup and should not be edited)
- Producing figures beyond the six in the spec
- Adding MRP-2026-03 metadata that isn't already in MRP-2026-02's convention (Sam adds the byline, MRP number, DOI; you assemble the slot for them)
- Re-running the corpus analysis (the data tables in the spec are canonical; if you want to verify a value, read the notebooks, not the bundles)

### Workflow

1. Read `figures-spec.md` end to end first. Then read the relevant `writeup-DRAFT.md` sections (§3, §4, §5, §6) to see where each figure lands.
2. Resolve the E1 style-anchor checkboxes against MRP-2026-02 once, in one short discovery pass. Surface anything you can't resolve to Sam before producing any figure.
3. Produce Figure 3 first — it's the load-bearing graphic. Get the styling right on this one, then carry the conventions across Figures 1, 2, 4, 5, 6.
4. Assemble the publication artefact per the doc-engine convention. Do not strip the DRAFT prefix until Sam OKs the figures and the reader-review pass is complete.
5. Report back with: paths to the rendered figures, paths to the assembled publication artefact, and any open style-anchor questions Sam needs to decide.

### Constraints

- Do NOT touch the `meshqu-research` repo from this session. All writeup edits, corrections, and data re-derivations happen there, not here.
- Do NOT edit `figures-spec.md` content (Sam owns it; if it's wrong, flag back).
- Do NOT add commentary or interpretation to figure captions beyond what the spec provides.
- DO match MRP-2026-02 conventions ruthlessly — visual continuity between E1 and E2 is one of the paper's load-bearing signals (it tells the reader these are part of the same programme, not one-off output).
